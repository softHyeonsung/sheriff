# 장소별 방문 기록 — 설계

> 2026-10-01 · 체크인 코어 보완 (코스 추천 ⑥-6보다 먼저)
> 근거: 사용자 결정("건물은 하나로 합치되 장소 방문 횟수는 따로"), `기획-기능명세-v1.md` §4.4(아지트=장소 묶기 ~15m), 체크인 코어 `2026-09-25-checkin-core-design.md`, 순간 남기기 `2026-09-30-memories-design.md`

## 문제

같은 건물(내 아지트 15m 안)의 다른 가게에서 발자국을 남기면 한 아지트로 합쳐진다. 그런데 발자국 기록(`checkins`)에는 아지트와 좌표만 남고 **어느 가게를 골랐는지는 남지 않는다.** 아지트에는 처음 만든 가게의 이름·카카오 장소 번호만 있다. 이 앱의 목적이 방문 장소 데이터인데 그 정보를 버리고 있다.

## 목표

아지트(건물)·등급·안개는 그대로 두고, **발자국마다 고른 장소를 기록**한다. 아지트 상세에서 "여기서 간 곳" 목록(장소별 방문 횟수)을 볼 수 있다.

**성공 기준**
- 1층 편의점 아지트가 있을 때 2층 카페를 골라 발자국 → 아지트는 하나, 발자국 수 +1, 기록에는 "2층 카페".
- 아지트 상세에 "여기서 간 곳": `편의점 1번 · 2층 카페 3번` 식으로 많이 간 순.
- 이미 있는 발자국은 그 아지트의 원래 장소로 채워진다.

## 결정 사항

| 결정 | 값 | 이유 |
|---|---|---|
| 저장 위치 | `checkins`에 `place_id text`(카카오 장소 번호, 없을 수 있음), `place_name text` | 장소별 횟수는 세면 나온다 — 별도 표 없음 |
| 카카오 후보를 골랐을 때 | 그 후보의 번호·이름 | 고른 장소 그대로 |
| 내 아지트를 골랐을 때 | 그 아지트의 원래 번호·이름 | 무엇을 갔는지 따로 묻지 않는다 |
| "새로 만들기" | 번호 없음, 이름 = 도로명 주소(없으면 아지트 이름) | 카카오에 없는 곳 |
| 기존 기록 | 아지트의 `kakao_place_id`·`name`으로 채움 | 개발 데이터뿐, 합쳐진 기록의 원래 가게는 복구 불가 |
| 같은 장소 판단 | 번호가 있으면 번호로, 없으면 이름으로 묶음. 표시 이름은 가장 최근 것 | 카카오에서 가게 이름이 바뀔 수 있음 |
| 합치기·쿨다운·등급·안개 | 그대로(아지트 단위) | 사용자 결정: 건물은 하나 |
| 사진 | 아지트 단위 그대로(장소별로 나누지 않음) | 범위 밖. 목록은 사진 올리는 화면(아지트 상세)에 같이 보인다 |
| GPS | 장소는 **사용자가 목록에서 고른 것**으로 정한다. GPS는 "150m 안에 있는가"만 본다 | 휴대폰 GPS는 15m 단위로 가게를 구분할 만큼 정확하지 않다(실내·도심 20~50m 오차) |

## 서버

마이그레이션 1개:
- `alter table checkins add column place_id text, add column place_name text` + 기존 행 채우기.
- `submit_checkin`(20260930000003 버전 + 장소 기록): `insert into checkins`에 장소 번호·이름을 함께. 결과 JSON은 그대로.
- `my_places(p_aidut uuid) returns table (place_id text, name text, visits int, last_visited_at timestamptz)` — 내 발자국만, 많이 간 순(같으면 최근 순). security invoker(기존 `checkins_select_own` 정책).

## 앱

| 파일 | 역할 |
|---|---|
| `features/map/useHideoutPlaces.ts` | `my_places` 불러오기(화면에 올 때마다), 상태 `loading·ready·offline·error` |
| `app/aidut/[id].tsx` | 헤더 아래·사진 버튼 위에 "여기서 간 곳" — 줄마다 `이름 · N번` |

- 한 곳뿐이고 이름이 아지트 이름과 같으면 목록을 숨긴다(헤더와 같은 말).
- 오프라인: "연결되면 간 곳을 보여드릴게요." 오류: 기존 공통 문구.

## 테스트

- pgTAP: 카카오 후보 → 번호·이름 기록, 내 아지트 → 아지트의 원래 장소, 새로 만들기 → 번호 없음, 15m 합쳐진 다른 가게가 따로 세어짐, `my_places` 순서·본인 것만·남의 아지트는 빈 결과, 기존 행 채우기.
- jest: 훅(성공·오프라인·오류), 상세 화면(목록·숨김 규칙·오프라인 문구).

## 범위 밖

- 사진을 장소별로 나누기, 장소별 등급·쿨다운, 체크인 시트에서 아지트의 다른 가게를 먼저 제안하기(지금도 목록에서 고를 수 있음), 다른 사람의 방문 통계, 코스의 "가본 곳" 판정 바꾸기.
