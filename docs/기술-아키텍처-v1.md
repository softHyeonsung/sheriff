> 작성일: 2026-09-22 · From: 개발팀(CTO) · 상태: v0.2 (백엔드 플랫폼 변경 반영)
> 근거: `핸드오프-개발팀-v1.md`, `기능명세-재개발기준.md`(현행 코드 전수분석), `기획-기능명세-v1.md`, `출시용-v1-범위정의.md`, `고양이-세계관-설계-v1.md`
> 성격: **클라이언트는 검증된 자산 승계. 백엔드는 Firebase → Supabase(Postgres+PostGIS)로 전환(2026-09-22 ADR, 확장성 우선).**
> 변경 이력: v0.1(Firebase 채택) → v0.2(Supabase 전환 — 공간 쿼리·관계형 확장성 근거로 재검토).

## 0. 아키텍처 헌법 (모든 기술 결정의 상위 기준)

1. **서버가 진실 원천 (Server-authoritative).** 성장·점수·뱃지·알림 생성은 서버 트랜잭션에서만. 클라이언트는 "요청"하고 서버가 "판정". → 현행 최대 부채(재개발기준 §9.1 점수↔규칙 충돌, 클라 조작 가능) 구조적 제거.
2. **얇은 네이티브 브리지 + 타입 계약.** RN↔WebView(카카오맵) 메시지를 discriminated union 타입으로 정의하고 HTML 템플릿·마커 SVG를 **단일 공유 모듈**로.
3. **오프라인 우선 핵심 루프.** 발자국 체크인은 로컬 큐잉 + 낙관적 UI, 동기화 실패 시 롤백.
4. **원격 상수화.** 성장 임계값·근접 반경·쿨다운·빈도 = 무배포로 튜닝 가능해야 함(§1.2 `app_config`).
5. **깊이 우선.** 4기둥 재건축 금지. 성장 한 축을 안정적으로.

## 1. 기술 스택 (확정)

### 1.1 클라이언트
| 레이어 | 채택 | 비고 |
|---|---|---|
| 런타임 | **Expo SDK 54 / RN 0.81 / React 19 / New Arch ON** | 승계 (managed+plugin) |
| 라우팅 | **expo-router 6** (`typedRoutes`) | 승계 |
| 언어 | **TypeScript strict** | `any` 금지 원칙 |
| 상태관리 | **Zustand** (도메인 슬라이스 재설계) | §7 |
| 지도 | **카카오맵 JS SDK → WebView 주입** | `react-native-maps` 의존성 **제거** |
| 위치/백그라운드 | **expo-location + expo-task-manager** (지오펜스) | v1 신규 |
| 알림 | **expo-notifications + FCM** | v1 신규 |
| 저장(로컬) | **expo-secure-store**(세션/약관), **AsyncStorage/MMKV**(체크인 큐·캐시) | |
| 애니메이션 | Reanimated / 축하·안개 연출 | |

> 클라이언트 스택은 변경 없음 — 지도가 WebView 주입이라 프레임워크 교체 이득 없고, 크로스플랫폼 개발 속도가 솔로/소규모 개발에 가장 중요.

### 1.2 백엔드 (Supabase — Postgres 기반)
| 서비스 | 용도 |
|---|---|
| **Postgres + PostGIS** | 주 데이터스토어. 좌표를 `geography` 컬럼으로 저장 → 공간 쿼리(`ST_DWithin`, `ST_Contains`) 네이티브 지원 |
| **Supabase Edge Functions** (Deno) | 성장 집계·뱃지·지오펜스 알림 트리거·외부 API 프록시. **모든 쓰기 권위** |
| **Postgres 트리거** | 승계된 Cloud Functions `onWrite` 역할(발자국→아지트 등급 재집계 등)을 DB 트리거로 대체 — 이동부품 감소 |
| **Supabase Storage** | 아지트 사진 (트랜잭션 업로드: Storage 기록 + doc 갱신을 하나의 Postgres 트랜잭션으로) |
| **Supabase Auth** | 카카오(커스텀 JWT 발급, Edge Function 경유)/구글/애플 OAuth |
| **FCM (직접 연동)** | 지오펜스 도착 푸시 — Edge Function에서 서비스 계정으로 직접 호출 |
| **`app_config` 테이블 + Realtime 구독** | 튜닝 상수(임계값·반경·쿨다운·빈도). 클라이언트가 Realtime으로 구독 → 무배포 반영 |
| **RLS (Row Level Security)** | 테이블 단위 접근 제어. §8 |
| **Turnstile/rate-limit (검토)** | 어뷰징 방지 — App Check 대체안, §11 열린 결정 |

**왜 전환했는가 (요약 ADR):** Firestore(NoSQL)는 안개탐험(공간 쿼리)을 geohash로 흉내내야 했고, 배열류 데이터를 서브컬렉션으로 쪼개는 등 관계형 데이터를 억지로 다뤄야 하는 부채가 이미 v0.1에서 드러남. PostGIS는 공간 쿼리가 1급 기능이고, 향후 소셜/관계형 확장(현재는 범위 밖이지만)이 훨씬 자연스러움. 초기 셋업 난이도·관리형 서비스로서의 운영 부담은 Firebase와 대등.

### 1.3 외부 API (전부 Edge Function 프록시 — 키 서버 보관)
Kakao Local(장소·주소·`coord2regioncode`) · Kakao Mobility(길찾기) · ODsay(대중교통) · TourAPI(주변 후보/코스). → 클라이언트는 Edge Function만 호출, REST 키 노출 제거(현행 `EXPO_PUBLIC_*` 부채 해소).

### 1.4 빌드·배포
EAS Build / EAS Update(OTA) / GitHub Actions(CI) / 원스토어·GP·App Store. 번들ID `com.hyeonsung.sheriff`(승계).

## 3. 클라이언트 아키텍처 (목표 모듈 구조)

거대 파일 분해(현행 `index.tsx` 2,326줄)를 **화면=조립, 로직=훅, 접근=서비스** 3계층으로.

```
src/
├─ app/                      # expo-router (화면 = 얇은 조립)
│   ├─ login  onboarding/  (tabs)/{map,profile}
│   ├─ aidut/[id]  checkin  wishlist  course
├─ features/                 # 도메인 로직 (UI 아님)
│   ├─ auth/       useAuthSession() ← supabaseUser ?? kakao_{id} 통합
│   ├─ checkin/    useProximityGate() useCheckin() (큐잉·낙관UI·롤백)
│   ├─ growth/     아지트 5단계·안개 개척률 파생 계산
│   ├─ geofence/   지오펜스 등록/해제, 백그라운드 태스크
│   ├─ cat/        고양이 상태·커스터마이즈·상주 애니메이션
│   ├─ wishlist/   찜 토글(로컬 즉시+서버, 재시도 큐)
│   └─ course/     코스 추천(TourAPI, 출발점 명시)
├─ map/                      # ★ 단일 브리지 모듈 (중복 제거)
│   ├─ webview-template.ts  markers.ts  protocol.ts(union+가드)  MapBridge.tsx
├─ services/                 # Supabase 클라이언트/RPC 래퍼 (SDK 직접호출 금지 경계)
├─ stores/                   # Zustand 슬라이스
├─ ui/                       # 디자인시스템(시맨틱 토큰, DESIGN.md)
├─ lib/                      # haversine, 행정구역 파서
└─ constants/                # KOREA_DISTRICTS 등
```

**원칙:** 화면은 훅만 호출(Supabase SDK 직접 import 금지). `useAuthSession()` 하나로 uid 통합. WebView 메시지는 `protocol.ts` union+타입가드로만(XSS 방어 승계).

## 4. 서버 아키텍처 (Supabase Edge Functions)

> 클라이언트 성장 쓰기 **전면 금지**. 아래가 유일한 쓰기 경로.

| 함수/트리거 | 유형 | 책임 |
|---|---|---|
| `kakao-custom-token` | Edge Function | 카카오 검증 → Supabase 커스텀 JWT 발급 → 유저 upsert(약관 재검증) |
| **`submit-checkin`** | Edge Function (RPC, DB 트랜잭션) | **신규 핵심.** 근접 게이트 서버 재검증(`ST_DWithin`) → 발자국 기록 → 아지트 성장(5단계) → 안개 셀 개척 → 쿨다운 검사 → 축하 반환 |
| **`on_checkin_insert`** | Postgres 트리거 (AFTER INSERT) | 발자국→아지트 등급/영역 진화 파생 재집계. Cloud Functions `onWrite`보다 지연 없음 |
| **`attach-memory`** | Edge Function | 사진 업로드 **트랜잭션화**(Storage→row 원자적) |
| **`register-geofences`** / pg_cron + FCM | Edge Function + 스케줄 | 지오펜스 셋 반환, 도착 푸시(쿨다운 6h·일 8회·야간DND·2분체류 — `app_config`) |
| `on_score_update` | Postgres 트리거 | 마일스톤 뱃지 서버 부여 |
| `kakao-directions`/`odsay-directions` | Edge Function | 인증·일 50회·키 서버보관 |
| `tour-nearby` | Edge Function | 신규 프록시(코스 후보) |

**제거:** `monthlySheriffBadge`(점수판 폐기), 모임 관련 전체.
**성장 파라미터(`app_config` 테이블):** 아지트 임계값(1/2~4/5~9/10~19/20+), 근접 반경 ~150m, 정확도 게이트 >150m 보류, 재방문 간격 6h|1일, 알림 쿨다운/상한. 기존 `postAggregation` 경계(1~2/3~6/7~14/15~29/30) **교체**.

## 5. 데이터 모델 (Postgres + PostGIS 재설계)

> 문자열 좌표·geohash 흉내 폐기 → **`geography(Point,4326)` 컬럼 + GIST 공간 인덱스**, 죽은 필드 제거, 공개/비공개 분리.

```sql
-- 비공개
users (uid PK, email, provider, terms_agreed_at, home_address)

-- 공개 읽기 분리(이메일 노출 차단) — RLS로 users와 분리
profiles (user_id FK → users, nickname, cat_name, cat_color, cat_pattern, territory_summary)

-- 발자국 원자기록 (Edge Function만 write)
checkins (id PK, user_id FK, aidut_id FK, coord geography(Point,4326), created_at)

-- 찜(저장 핀 승계)
wishlist (user_id FK, place_id, created_at)

-- 개척된 셀(안개 걷힘 단위) — 격자 셀 자체는 PostGIS geometry로 생성, PostGIS 함수로 소속 판정
fog_cells (user_id FK, cell_id, explored_at)

-- 아지트
aidut (id PK, road_address, coord geography(Point,4326), owner_uid FK,
       footprint_count, grade text /* 🐾📦🛖🗼🏰 */)
aidut_tenants (aidut_id FK, user_id FK)          -- 배열 대신 조인 테이블
aidut_memories (id PK, aidut_id FK, photo_url, created_at)  -- 사진(고양이의 추억), 트랜잭션 첨부

-- 거시(동 단위 진화) 캐시
territory (uid PK, dong_stats jsonb, explored_ratio numeric)
```

- **좌표 전부 `geography` + GIST 인덱스** (안개 셀 개척·주변 조회는 `ST_DWithin`/`ST_Intersects`로 직접 쿼리 — geohash 수작업 불필요).
- 배열류 → 조인 테이블(모임 없으니 스키마 부담 적음, 있어도 표준 SQL로 해결).
- **제거:** `posts`·`gatherings`·`chats`·`quests`·`place_saves`·죽은 필드.
- **묶기:** 도로명주소+좌표 근접 ~15m(`ST_DWithin(coord, ..., 15)`), 애매하면 독립 아지트.

## 6. 핵심 신규 인프라

### 6.1 지오펜스 도착 알림
`expo-task-manager` 백그라운드 지오펜스(내 아지트+찜, 근접순 — iOS 20개 한도 관리) → 진입 → 2분 체류 → FCM → 알림 탭 시 체크인 딥링크. iOS "항상 허용" 병목: 온보딩 강요 금지, 승낙률 초기 지표.

### 6.2 근접 게이트 체크인 (서버 재검증)
클라 1차 게이트(~150m) → `submit-checkin` 서버 2차 검증(`ST_DWithin` + 정확도·쿨다운) → 트랜잭션 성장. 오프라인: 로컬 큐 + 낙관 UI → 온라인 확정, 거절 시 롤백.

### 6.3 안개 탐험 (fog of war)
지도를 격자 셀로 덮고 발자국 셀만 `fog_cells`에 개척 → 걷힘. 개척률 = 개척 셀/동 격자 셀(PostGIS 공간 조인으로 집계). 고양이는 걷힌 영역에서만. **감쇠 없음.**

## 11. 열린 결정 / 리스크
1. 로컬 저장소: MMKV vs AsyncStorage (체크인 큐 신뢰성 기준).
2. 지오펜스 OS 한도: iOS 20개 → 근접순 동적 재등록 전략.
