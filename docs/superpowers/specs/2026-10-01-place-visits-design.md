# 장소별 방문 기록 — 설계

> 2026-10-01 · 체크인 코어 보완 (코스 추천 ⑥-6보다 먼저)
> 근거: 사용자 결정("건물은 하나로 합치되 장소 방문 횟수는 따로"), `기획-기능명세-v1.md` §4.4(아지트=장소 묶기 ~15m), 체크인 코어 `2026-09-25-checkin-core-design.md`, 순간 남기기 `2026-09-30-memories-design.md`

## 문제

같은 건물(내 아지트 15m 안)의 다른 가게에서 발자국을 남기면 한 아지트로 합쳐진다. 그런데 발자국 기록(`checkins`)에는 아지트와 좌표만 남고 **어느 가게를 골랐는지는 남지 않는다.** 아지트에는 처음 만든 가게의 이름·카카오 장소 번호만 있다. 이 앱의 목적이 방문 장소 데이터인데 그 정보를 버리고 있다.

## 목표

아지트(건물)·등급·안개는 그대로 두고, **발자국마다 고른 장소를 기록**한다. **사진도 어느 장소에서 남겼는지** 기록한다. 아지트 상세에서 "여기서 간 곳" 목록(장소별 방문 횟수)과 사진별 장소를 볼 수 있다.

**성공 기준**
- 1층 편의점 아지트가 있을 때 2층 카페를 골라 발자국 → 아지트는 하나, 발자국 수 +1, 기록에는 "2층 카페".
- 아지트 상세에 "여기서 간 곳": `편의점 1번 · 2층 카페 3번` 식으로 많이 간 순.
- 2층 카페로 발자국을 남긴 뒤 사진을 남기면 그 사진은 "2층 카페"로 기록되고, 크게 볼 때 장소 이름이 보인다.
- 이미 있는 발자국·사진은 그 아지트의 원래 장소로 채워진다.

## 결정 사항

| 결정 | 값 | 이유 |
|---|---|---|
| 저장 위치 | `checkins`에 `place_id text`(카카오 장소 번호, 없을 수 있음), `place_name text` | 장소별 횟수는 세면 나온다 — 별도 표 없음 |
| 카카오 후보를 골랐을 때 | 그 후보의 번호·이름 | 고른 장소 그대로 |
| 내 아지트를 골랐을 때 | 그 아지트의 원래 번호·이름 | 무엇을 갔는지 따로 묻지 않는다 |
| "새로 만들기" | 번호 없음, 이름 = 도로명 주소(없으면 아지트 이름) | 카카오에 없는 곳 |
| 기존 기록 | 아지트의 `kakao_place_id`·`name`으로 채움 | 개발 데이터뿐, 합쳐진 기록의 원래 가게는 복구 불가 |
| 같은 장소 판단 | 번호가 있으면 번호로, 없으면 이름으로 묶음. 표시 이름은 가장 최근 것 | 카카오에서 가게 이름이 바뀔 수 있음 |
| 합치기·쿨다운·등급·안개 | 그대로(아지트 단위) | 사용자 결정: 건물은 하나 |
| 사진의 장소 | `aidut_memories`에 `place_id`·`place_name`. `attach_memory`가 **그 아지트에서 내가 가장 최근에 남긴 발자국의 장소**를 그대로 붙인다 | 사용자 결정: "여기 ○○ 맞냥?"에서 사용자가 말해 준 장소를 따른다. 사진 찍을 때 다시 묻지 않는다 |
| 사진 표시 | 크게 보기에 "{장소 이름}에서" 한 줄 | 타일은 지금 그대로 |
| 대기 중이던 사진 | 올라가는 시점의 가장 최근 발자국 장소 | 알고 둔 한계: 사진이 올라가기 전에 같은 건물의 다른 가게로 또 발자국을 남기면 그 가게로 기록된다(드묾) |
| GPS | 장소는 **사용자가 목록에서 고른 것**으로 정한다. GPS는 "150m 안에 있는가"만 본다 | 휴대폰 GPS는 15m 단위로 가게를 구분할 만큼 정확하지 않다(실내·도심 20~50m 오차) |

## 서버

마이그레이션 1개:
- `alter table checkins add column place_id text, add column place_name text` + 기존 행 채우기.
- `submit_checkin`(20260930000003 버전 + 장소 기록): `insert into checkins`에 장소 번호·이름을 함께. 결과 JSON은 그대로.
- `aidut_memories`에 `place_id text`, `place_name text` + 기존 행 채우기. `attach_memory`가 넣을 때 최근 발자국의 장소를 붙인다(인자·반환은 그대로 — 앱의 올리기·대기열 코드는 안 바뀐다). `my_memories`가 `place_name`도 돌려준다.
- `my_places(p_aidut uuid) returns table (place_id text, name text, visits int, last_visited_at timestamptz)` — 내 발자국만, 많이 간 순(같으면 최근 순). security invoker(기존 `checkins_select_own` 정책).

## 앱

| 파일 | 역할 |
|---|---|
| `features/map/useHideoutPlaces.ts` | `my_places` 불러오기(화면에 올 때마다), 상태 `loading·ready·offline·error` |
| `features/memories/memoriesApi.ts` | `MemoryPhoto`에 `placeName` |
| `app/aidut/[id].tsx` | 헤더 아래·사진 버튼 위에 "여기서 간 곳" — 줄마다 `이름 · N번`. 사진 크게 보기에 "{장소 이름}에서" |

- 한 곳뿐이고 이름이 아지트 이름과 같으면 목록을 숨긴다(헤더와 같은 말).
- 오프라인: "연결되면 간 곳을 보여줄게냥." 오류: "간 곳을 불러오지 못했다냥."

## 테스트

- pgTAP: 카카오 후보 → 번호·이름 기록, 내 아지트 → 아지트의 원래 장소, 새로 만들기 → 번호 없음, 15m 합쳐진 다른 가게가 따로 세어짐, `my_places` 순서·본인 것만·남의 아지트는 빈 결과, 발자국 없는 아지트의 사진은 아지트의 원래 장소, `attach_memory`가 최근 발자국의 장소를 붙임(다른 가게로 발자국을 남긴 뒤엔 그 가게), `my_memories`의 `place_name`.
- jest: 훅(성공·오프라인·오류), 상세 화면(목록·숨김 규칙·오프라인 문구·크게 보기의 장소 이름), `listMemories`의 `placeName`.

## 범위 밖

- 사진 찍을 때 장소를 다시 고르기·사진의 장소 고치기, 장소별 등급·쿨다운, 다른 사람의 방문 통계, 코스의 "가본 곳" 판정 바꾸기.

## 덧붙임 (2026-10-01)

재방문 때 그 건물에서 간 곳을 많이 간 순으로 먼저 제안한다(사용자 결정). `nearby_my_places` RPC가 반경 안 내 아지트들의 간 곳을 주고, `suggest-place`가 아지트의 원래 가게는 아지트 후보로, 다른 가게는 아지트 좌표를 가진 카카오 후보로 내보낸다 — 고르면 같은 아지트로 합쳐지고 그 가게로 기록된다.
